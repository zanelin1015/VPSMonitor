# Realm 周期流量

每条 Realm 转发规则按监听 IP、端口和协议独立计量，支持查看上行、下行与合计。日期范围以北京时间计算，包含起止日期当天，单次最多查询 366 天。

## 启用

1. 更新 Server 与对应机器上的 Client。Server 提供保存、查询和界面，Client 提供实际计数。
2. Client 运行在原生 Linux 上，具有 root 或 `CAP_NET_ADMIN` 权限，并可执行 `nft`。缺少命令时，在该 Linux 主机安装发行版的 `nftables` 软件包。
3. 总管理员打开 Client 详情 → Realm → Realm 转发，开启“统计端口流量”，保存配置。
4. 在 Realm → 周期流量中选择日期，或使用“今日”“近 7 天”“本月”。等待后续 Client 上报后刷新查询。

功能默认关闭，现有部署不会自动创建计量规则。开启、关闭计量本身不会重启 Realm。OpenWrt/iStoreOS 当前不启用此采集，避免改动 firewall4；容器端口映射场景应由宿主机部署采集 Client。

## 统计口径

- 上行：到达 Realm 监听端口的网络字节；下行：从该监听端口返回客户端的网络字节。TCP 与 UDP 按规则合计，包含网络包头、确认包、重传及该端口收到的其他报文，区别于 x-ui 应用层流量。
- 只计监听侧，不再叠加 Realm 到目标机器的另一段连接。同一链路的不同中转机器分别保存记录，整条链路的使用量应选定一跳作为口径，不能直接将所有跳相加。
- 从首次有效上报建立基线，启用前或未曾采集的历史不能补算。每段增量归入当前采样的北京时间日期，日期边界精度取决于上报间隔；长时间断报跨日时无法精确拆分。
- Client/Realm 重启复用内核计数器；主机重启或计量表重建产生新代次，避免因计数器归零、或者新计数已超过旧值而产生错误差额。主机重启前尚未上报的尾部数据无法保证恢复。
- 区域账号仅可查询其已获授权的 Realm 监听端口。仅有落地客户端权限不会获得整个入口端口的流量权限。

## 实现与数据

使用 [nftables 命名计数器](https://wiki.nftables.org/wiki-nftables/index.php/Counters)，仅维护 `inet vpsmonitor_realm_traffic` 表及其中的 input/output 计数链。规则不包含放行、丢弃、转发或限速动作，也不会清空系统规则。该功能不要求启用或重载系统 nftables 服务。

Server 将采样基线写入 `realm_traffic_counters`，增量按天写入 `realm_traffic_daily`。重复、延迟上报会被忽略；采集失败不作为零流量写入。每日汇总独立于原始快照清理保存，删除 Client 时一并删除其流量记录。

查询接口：`GET /api/v1/agents/{agent_id}/realm/traffic?from=2026-11-01&to=2026-11-18`。返回统计起点、最近采集时间、采集状态和每条规则的周期用量。缺少 nftables、权限不足、Realm 未运行等错误会显示在查询页；失败时历史记录仍可查询。
